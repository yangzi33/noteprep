## 1. 用户问题

独立的私人数学辅导老师备课时,要同时产出:讲义、分层练习、独立答案和逐步解答,并排成可打印的版面。手工完成耗时,而且答案或步骤出错会直接损害老师的信誉。

通用聊天式 AI 的主要问题:数学可能出错且无法核对、输出不可编辑成稳定结构、排版不可直接打印、学生版与答案版容易混在一起。

**核心价值主张(待验证,不是已证实的结论):** 用更少的备课时间,得到课程感知、数学经过确定性检查、排版专业的课包(预览与预设调整,而不是自己编辑)。

## 2. MVP 范围

### 2.1 包含

| 项 | 说明 |
|---|---|
| 学科 | 仅 Math。首个验收路径:一元一次方程(linear equations in one variable) |
| 账户 | 个人辅导老师账户(Supabase Auth,须验证邮箱) |
| 输入 | **选择**:课程体系 → [级别] → 课程 → 单元/主题(来自有来源的课程数据集;只有同时具备验证能力的主题可选),再选课时、难度与输出包。不再有自由文本字段 |
| 输出 | 课包 = 所请求文档的真正编译的 PDF:**Tutor Lesson Notes、Student Practice Worksheet、Solutions/Answer Key**(完整包三份)。规范数据源是结构化内容;`.tex` 只是内部派生物,**不提供给用户**(D-31) |
| 调整 | **预览 + 预设快速调整 + 极小的文字更正**(不改数学);不再有内容编辑器(D-34) |
| 历史 | 课包列表、各修订版本、导出、剩余额度 |
| 计费 | 终身 3 次免费完整生成(无需信用卡);之后一个 Stripe 月订阅方案 |

### 2.2 非目标(首版明确不做)

其他学科、学生账户、实时授课、排课、CRM、团队与权限、协作编辑、题库市场、RAG、文件上传、任意 URL 抓取、自动学情诊断、幻灯片、任意用户 `.tex` 上传或在线 TeX 执行。导出的 `.tex` 可以由老师在本地自由修改,系统不会再次接收它。

- 界面语言与课件语言:英文;纸张:A4;课程对齐声明**只能**来自所选的、受支持的课程数据集(MVP 目标:Ontario Grade 9 数学,D-30;真实数据集与授权是之后的独立里程碑,在此之前只用明确标注的示例数据,且不得用于对齐声明)。"学习程度"是自由选项(如 "Grade 7-8 equivalent"),只作为难度提示。
- 目标市场、币种、课程标准均未确定,不由对话语言推断。

## 3. 端到端流程

```
登录 → 选择 课程体系/级别/课程/主题 + 课时/难度/输出包 → 提交(幂等键,入队时解析课程上下文)
     → 查看任务进度(排队/生成/验证/编译/保存) → 预览 Notes / Worksheet / Solutions
     → 预设快速调整 或 极小的文字更正 → 导出 PDF → 历史记录与剩余额度 → 订阅/管理账单
```

要点:

1. 提交只做"校验 + 事务内预留额度 + 入队",立即返回 job ID;刷新页面或关闭浏览器不会丢任务。
2. 生成成功 = 同一事务内:修订版本发布 + 所请求文档的 PDF 清单提交 + 额度消耗 + 任务标记 succeeded。
3. 任何终态失败或有效取消 = 额度释放,不消耗免费次数。
4. 预览、导出、重新渲染/编译、文字更正,以及**不调用模型的确定性调整**都不是"新生成",不消耗生成次数,但受速率与计算配额限制;**含模型的调整**消耗每课包的调整额度(与生成次数分开,配置值,D-33),同样遵循成功才消耗、失败返还、一次结算。

## 4. 免费 3 次与订阅:精确语义

### 4.1 术语

- **完整生成(complete generation)**:一次新的 AI 课包生成,通过结构与数学检查,所请求的每份文档(Notes、Worksheet、Solutions)的 PDF 均已保存并可通过授权下载获取。是否计费只看服务端事实,**与浏览器是否收到成功响应无关**。
- **bucket**:额度桶。`trial`(每账户终身一个,limit=3)或 `paid`(每个已验证的 Stripe 订阅计费周期一个)。
- **reservation**:任务入队时从某个 bucket 预留的 1 次额度;状态单向 `reserved → consumed | released`。

### 4.2 规则

| # | 规则 |
|---|---|
| R1 | 每账户一个 trial bucket,`limit=3`,约束 `used + reserved <= limit`。删除课包、登出、重复注册回调、订阅变化都不会重置。 |
| R2 | 额度来源在入队时固定(trial 或某个 paid bucket),完成时不再重选。 |
| R3 | 有有效订阅(status=active 且在周期内)时,新任务只使用付费周期 bucket;免费剩余次数**不叠加、不并行消耗**。订阅失效后只能使用原免费剩余次数。(对 CLAUDE.md "paid bucket first / 不叠加"的保守解读,见 [decisions](decisions.md) D-07,待确认。) |
| R4 | 只有 `reserved → consumed` 计入使用;`released` 不计入。同一事务内完成:发布修订 + 标记 succeeded + 消耗预留,最多一次。 |
| R5 | 终态失败(生成/验证/编译/上传/预算耗尽)与有效取消均释放预留。自动重试复用同一预留。 |
| R6 | 释放额度**不**释放速率、尝试次数与成本限制(见 architecture §6.6)。 |
| R7 | 同一账户同时在途任务数有上限;额度不足时第 4 次(无有效订阅)被拒绝并引导订阅。 |
| R8 | 删除成果不退还已消耗次数。订阅到期后,用户仍可查看、预览、调整(受配额限制)、重新渲染、导出自己的历史成果(账户未删除时)。 |
| R9 | 免费结果不加水印、不缺答案、不降级导出。 |
| R10 | 订阅周期开始时按配置的额度创建 paid bucket(周期标识唯一),重复事件/同步不会重复发放;跨周期在途任务用原 bucket 结算,不借下一周期额度。 |
| R11 | 用户界面显示"剩余 = limit − used − reserved",并单独显示"进行中(已预留)"数量,避免用户误解。 |

### 4.3 付费方案

首版一个月订阅方案,**价格、币种、每期额度均未确定**,设计为配置(`PAID_PERIOD_GENERATION_LIMIT` 等)。测试与示例中出现的任何额度数字必须标注为 `TEST VALUE`,不是商业决定。默认不提供无限使用。

## 5. 用户可见状态

queued(排队)· running + 阶段 generating / validating / compiling / storing · succeeded · failed(显示可操作原因与是否可重试)· canceled · allowance-exhausted(额度用完,引导订阅)· timed-out(归类为 failed,原因 timeout)。

## 6. 验收场景(Given/When/Then,全部待用证据证明)

| ID | 场景 |
|---|---|
| AS-01 | 新账户完成第 1、2、3 次生成均成功;剩余额度依次为 2、1、0;第 4 次提交被拒绝并给出订阅入口。 |
| AS-02 | 已完成 2 次的账户同时提交两个新任务:恰好一个被接受,另一个得到"额度不足(有 1 个任务进行中)"。若第一个最终失败,额度回到 1。 |
| AS-03 | 同一幂等键、同一请求重试:返回原 job,不重复预留;同一键、不同请求:409 冲突。 |
| AS-04 | 生成过程中模型超时/数学不通过/编译失败/上传中断:任务 failed,预留 released,已用次数不变。 |
| AS-05 | 成功后可预览并导出所请求的 PDF(完整包为 Notes、Worksheet、Solutions 三份);Worksheet 中不含独立练习答案;不提供 `.tex`。 |
| AS-06 | 数学内容不可手改:应用"更难/更容易"等调整会重新生成受影响的练习及其解答(解答随练习一致),**未受影响的节与调整前逐字节相同**;文字更正只能改文字字段,且文字中不得出现课程声明。 |
| AS-09b | 选择:只显示所选课程体系的级别/课程/主题;更改上一步会清空后续选择;不受支持的主题灰显,且服务端拒绝提交。 |
| AS-09c | 课程对齐:课包里每处对齐声明都能追溯到所选的、受支持的课程数据集版本;没有数据集支持就没有对齐声明。 |
| AS-07 | 订阅过期后:仍可查看/编辑/重新编译/下载历史成果,但不能创建新的付费生成。 |
| AS-08 | 用户 A 无法读取/下载/取消用户 B 的课包、任务、文件、账单入口。 |
| AS-09 | Checkout 成功页在 webhook 处理前只显示"确认中",不开通付费额度;处理后才出现 paid bucket。 |
| AS-10 | 浏览器返回/刷新/网络重试不丢失任务,不重复消耗额度。 |

## 7. 成功指标(定义与未来测量方式;当前无任何实际数据)

| 指标 | 定义 | 测量来源 |
|---|---|---|
| 完整生成成功率 | `succeeded` 的 generate 任务 / 已结束的 generate 任务(排除用户取消),按失败原因分层 | GenerationJob 表 |
| 数学验证覆盖率 | 课包中 verified 题数 / 总题数;另报 failed 与 unverified 占比 | 修订版验证报告 |
| 生成耗时 | 入队到 succeeded 的 p50/p95,分阶段耗时 | 任务阶段计时 |
| 单课包成本 | 成功任务的 LLM 成本 +(估算的)计算成本;失败任务成本单独统计 | 任务 token/成本记录 |
| 返工成本 | 失败/重试任务消耗的成本 / 成功任务成本 | 同上 |
| 调整使用率 | 生成后 7 天内应用至少一次调整的课包比例,及调整后导出率(代理指标) | 修订版表 + 调整作业 |
| 试用到订阅转化 | 用完 3 次免费的账户中,N 天内创建有效订阅的比例 | Subscription + Bucket |
| 人工数学抽查错误率 | 人工抽查课包中发现的数学错误数 / 抽查题数(上线前必须有) | 人工抽查记录 |

指标阈值和目标值在有真实数据前**不设定**。
