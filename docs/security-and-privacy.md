# 安全与隐私

> 状态:设计层面的威胁模型与计划。**不声称任何防护已实现、已测试或已通过合规认证。** 每条"验证"都对应 [test-plan](test-plan.md) 中尚未执行的测试。
> 相关:[architecture](architecture.md) · [decisions](decisions.md)

## 1. 资产与信任边界

资产:教师账户、备课输入、课包内容(可能含教师私有教学思路)、订阅状态、各类凭据(LLM、Stripe、Supabase secret、数据库)。

```
[浏览器] ──不可信── [Vercel Web] ──半可信── [Postgres / Storage(Supabase)]
                          │                         ▲
                          └──── 任务入队 ───────────┤
                                                   [Worker] ──可信代码(处理不可信数据)── [LLM 供应商 / Stripe]
                                                      │
                                                   [Runner] ── 无秘密账户
                                                      │
                                                   [沙箱] ── 完全不可信的执行环境(处理由模板+转义内容生成的 TeX)
```

边界规则:

1. 浏览器、用户备注、LLM 输出、Stripe webhook 请求体(验签前)、编译产物 —— 一律视为不可信数据。仓库内容、外部材料或 LLM 输出里嵌入的"指令"不构成额外权限。
2. Web 与 worker 之间只通过数据库交互,没有 Web→worker 的直接调用通道。
3. 沙箱与 worker 之间只有 stdin/stdout 的 tar 通道。

## 2. 数据清单

| 数据 | 位置 | 用途 | 说明 |
|---|---|---|---|
| 邮箱、认证标识 | Supabase Auth;`Profile.id` 映射 | 登录、验证邮箱、账单联系 | 要求验证邮箱 |
| 备课输入(主题、程度、目标、课时、难度、题量、备注) | `Lesson.inputSpec` | 生成 | 备注框提示"请用匿名描述,勿填学生姓名/联系方式/成绩/健康信息";测试与演示只用虚构数据 |
| 课包内容与修订 | `LessonRevision.content` | 编辑、导出 | 属于用户内容 |
| 产物文件 | 私有 Storage | 下载 | 路径服务端生成 |
| 任务元数据(状态、阶段、耗时、token、成本、错误类型) | `GenerationJob` | 运行、核算、告警 | **不含内容正文** |
| 订阅状态、周期、价格 ID、Stripe 客户/订阅 ID | `Subscription`、`Profile` | 权益 | 不存卡号/安全码;不存完整 webhook 载荷 |
| Webhook 事件元数据 | `WebhookEvent` | 去重、排障 | 仅 ID、类型、对象 ID、状态、错误码 |
| 速率限制计数、IP 哈希 | `RateLimitWindow` | 滥用控制 | IP 使用加盐哈希,有限保留 |
| 邮箱 HMAC(待决策 D-08) | `TrialTombstone` | 防止删号重注册重置试用 | 需披露保留目的与期限 |

**发给 LLM 的字段(最小化):** 题型与难度标签、学习程度、学习目标、课时、经过清理的补充备注、任务所需的结构化约束。**不发送:** 邮箱/账户标识、账单信息、其他用户的课包、内部日志、完整历史。供应商作为子处理方在隐私政策中如实披露;保留期与"是否用于训练"以其官方条款为准,**不自行承诺零保留或不训练**。

**日志/指标/错误上报:** 只记录 request ID、job ID、阶段耗时、错误类型、token/成本、重试次数、validatorVersion。**禁止**记录课包正文、学生信息、JWT、签名 URL、完整提示词、Stripe 秘密/完整载荷。需有自动化检查(日志样例扫描)。

## 3. 最小权限

| 主体 | 权限 | 备注 |
|---|---|---|
| 浏览器 | 仅 publishable key + 自己的会话 | 不能直接读写业务表;`anon`/`authenticated` 对业务表无授权,并开启 RLS(无策略) |
| Web 运行时(`app_runtime`) | 业务表必要 DML;无 DDL;无 BYPASSRLS/CREATEDB | 不持有 LLM key、Supabase secret key |
| Worker(`worker_runtime`) | 任务/修订/额度/事件相关 DML;Storage 写删(secret key);LLM key;Stripe 受限 key | 无迁移权限 |
| 迁移(`migrator`) | DDL | 仅在受保护 CI 环境、需审批;不在运行时环境 |
| Runner 账户 | 仅能启动沙箱 | 无任何业务凭据 |
| 沙箱 | 无 | 无网络/环境变量/挂载;非 root;只读根;能力全丢弃 |
| GitHub Actions | 最小 `permissions`;第三方 action 固定到提交 SHA;外部 PR 不暴露秘密,不用特权事件执行不可信 PR 代码 | |

Supabase 官方 Prisma 指南为 `prisma` 角色授予 `bypassrls` 与 `createdb`;**本项目不采用**。Service-role/secret key 不受 RLS 约束,仅用于明确的服务端边界(worker),且使用前必须已有归属校验。

## 5. 请求与会话层面的细则

- Server Actions/Route Handlers 校验请求大小,限制 JSON 深度与字符串长度;输入使用 Zod。
- 重定向目标使用白名单;Stripe `success_url`/`cancel_url` 由服务端固定拼接。
- 下载接口:先授权,再签发 ≈60 s 的签名 URL;响应 `no-store`;不把签名 URL 写入日志。
- 速率限制与 IP:仅信任部署平台设置的转发头(Vercel 行为须核实);IP 哈希加盐。

## 6. 保留策略(**待定**,上线前必须确定)

| 数据 | 初步建议(未决) |
|---|---|
| 课包与产物 | 保留至用户删除或账户删除;订阅到期不删除 |
| `rejected` 失败草稿 | 短期保留供查看后清除(期限待定) |
| 任务元数据 | 为核算与排障保留固定期限(待定),不含内容 |
| Webhook 事件元数据 | 固定期限后清除 |
| 速率限制计数 | 窗口过期后清除 |
| 备份 | 备份中的删除有延迟,需在隐私政策里说明 |
| 账单相关记录 | 因税务/会计/争议需要的最短期限内保留(期限由用户与顾问确定) |

## 7. 删除流程

**课包删除:** ① 置 `Lesson.deletedAt`(立即阻断读取/下载;在途任务提交时检查并放弃)→ ② 取消在途任务并释放预留 → ③ 异步清理对象与修订记录 → ④ 保留不含内容的任务/用量记录用于核算。已消耗次数不退还。

**账户删除:** ① `Profile.status='deleting'`(阻止新建任务与发布)→ ② 取消在途任务并释放预留 → ③ 服务端取消 Stripe 订阅(**立即取消还是期末取消、是否退款:待定 D-09**)→ ④ 删除全部对象与课包记录 → ⑤ 通过 worker 删除 Supabase Auth 用户 → ⑥ 保留必要的账单记录与(若采用)邮箱 HMAC 墓碑,本地订阅记录去标识化 → ⑦ 记录备份中的延迟擦除窗口。每一步幂等、可重试;恢复流程**不得**复活已进入删除态的内容。

## 8. 合规与披露(未确定事项)

- 数据地区、第三方跨境传输、隐私政策、服务条款、cookie/同意需求:均**未确定**,不声称任何法律或认证合规。
- 子处理方披露至少包含:Supabase、Vercel、Stripe、LLM 供应商、Worker 主机提供商;各自的目的与保留期以其官方条款为准。
- 面向儿童/学生数据:产品设计上不收集学生身份信息;若用户在备注中输入,风险由提示语与最小化处理控制,**不能保证完全避免**。

## 9. 尚未确定/待验证

0. **JWT 签名算法(P1-T5 实测发现,上线门槛)**:只要项目仍启用旧的 HS256 共享密钥,持有该密钥的人就能为任意用户 ID 伪造被 Auth 服务端(`getUser`)乃至 `getClaims` 接受的令牌(本地栈实测;本地 demo 密钥是公开的)。应用层 `verifyClaims` 只接受 ES256/RS256/EdDSA 并有测试;**托管项目还必须使用非对称签名密钥并撤销旧密钥**,上线前在 Supabase 控制台核对。另:`getClaims` 只做本地验签,登出/撤销后令牌在过期前仍可通过(已有测试记录),所以计费、删除等敏感操作使用 `getUser()`。
1. 下载签名 URL 是否可由用户会话客户端在 RLS 下直接签发(待用本地 Supabase 实测);否则 Web 需要额外持有受限服务端凭据。
2. gVisor 在目标主机上的兼容性与逃逸后果隔离(runner 账户机制)。
3. Stripe 受限 key 的最小权限集合;API 版本固定。
4. 邮箱 HMAC 墓碑的取舍与披露(D-08)。
5. 退款/争议策略与账户删除时订阅的处理(D-09/D-10)。
6. 数据地区与保留期、隐私政策文本。
